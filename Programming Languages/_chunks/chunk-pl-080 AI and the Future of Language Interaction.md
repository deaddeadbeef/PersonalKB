# chunk-pl-080 AI and the Future of Language Interaction

LLMs are changing how developers interact with languages.

**AI-friendly languages:** Languages that are easy for LLMs to generate correctly:
- **Rust:** The compiler catches AI mistakes. Strong types validate generated code. If it compiles, it probably works.
- **TypeScript:** Types guide generation. Autocomplete and type checking validate AI output.
- **Python:** Widely represented in training data. Simple syntax reduces generation errors.

**AI-unfriendly characteristics:** Implicit behavior (C++ template errors), complex macro systems, unusual syntax (APL), weak type systems (no compiler to catch mistakes).

**The IDE shift:** AI assistants (Copilot, Cursor) are changing the value proposition of languages. A verbose language (Go, Java) is less painful when AI writes the boilerplate. An expressive language (Haskell) is less advantageous when AI handles the abstractions.

**Language design implications:** Future languages may optimize for: human readability (review AI output), type system expressiveness (validate AI output), and clear error messages (help AI fix mistakes).

The compiler as AI validator: strong type systems become more valuable when AI generates code, because the compiler catches what the AI gets wrong.
