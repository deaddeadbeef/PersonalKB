# Cryptography — Pseudorandom bit generation from a short seed approximates the security of a one-time pad

## Context

Cormen introduces the randomness requirement in Chapter 8 in the context of why cryptographic systems need good random numbers. The one-time pad achieves perfect secrecy but requires a key as long as the message — impractical for bulk data. The practical resolution is a **pseudorandom bit generator (PRBG)**: a deterministic algorithm seeded with a short, secret value that produces a long output stream which appears random to an observer who does not know the seed.

The PRBG output can be XOR'd with plaintext to function as a one-time pad, but the secret that must be protected is only the short seed — not a key as long as the message. The seed itself is generated locally and kept secret; it is not transmitted. How parties agree on shared key material is a separate concern, handled in practice by hybrid encryption (e.g., RSA encrypts a randomly generated session key so only the intended recipient can decrypt it).

## Why It Matters

Poor randomness is a practical attack vector that bypasses mathematically sound algorithms entirely. If the seed is predictable, short enough to enumerate, or reused across sessions, an adversary can reconstruct the keystream and decrypt ciphertext — regardless of RSA key length or cipher strength. The security of a cryptosystem depends on the unpredictability of key material as much as on the hardness of the underlying mathematical problem.
