# Broker APIs and Automation Controls

## One-Line Summary

A broker API turns software mistakes into order messages, so controls, logs, and shutoff paths must exist before any automation touches an account.

## API Boundary

An API key, trading token, or broker integration is market access. Even when a broker provides a paper environment, the program must be written as if a routing bug could become real. SEC and FINRA materials on market access and algorithmic trading emphasize pre-trade controls, supervision, testing, and post-trade review because automated order flow can fail quickly.

For this wiki, API work is an engineering practice topic before it is a trading topic.

## Required Controls

| Control | Rule |
| --- | --- |
| Environment separation | Paper keys and live keys must never share config names |
| Credential handling | Keys stay out of notes, commits, screenshots, and logs |
| Symbol allowlist | The program can trade only explicitly allowed symbols |
| Quantity limit | Every order is capped before it reaches the API |
| Notional limit | Every order has a maximum dollar value |
| Position limit | New orders are blocked after maximum exposure |
| Daily-loss limit | The process shuts down after a defined loss threshold |
| Order-rate limit | Loops cannot flood the API with duplicate orders |
| Price guard | Limit prices, spreads, and stale quotes are checked before submission |
| Kill switch | One manual action can disable new orders immediately |
| Audit log | Every signal, decision, request, response, cancel, fill, and error is saved |

## Paper-Only API Checklist

Before using any broker API, even in paper mode:

| Field | Required entry |
| --- | --- |
| Broker and environment | Name paper environment only |
| Credential location | Describe secure local storage without exposing secrets |
| Allowed symbols | List the explicit allowlist |
| Allowed order types | List only the order types studied in [[Order Types and Execution]] |
| Maximum order size | Define share and notional caps |
| Maximum position size | Define total exposure cap |
| Maximum daily loss | Define stop threshold |
| Kill-switch command | State exact manual shutdown method |
| Log file location | State where review evidence is stored |
| Dry-run proof | Link to the paper run or simulation log |

## Forbidden First-Pass Behavior

- No live API keys.
- No margin, short selling, options, leveraged ETFs, or rapid intraday strategy.
- No market orders generated by an unattended script.
- No strategy that depends on sub-second reaction time.
- No code that can trade all symbols by default.
- No code that retries failed orders without a hard retry limit.
- No hidden credentials in Obsidian notes or Git.
